## 应用接入全流程

### 一、基本信息提交

请提供以下应用接入基本信息：

```yaml
# 示例信息
厂商名称: 蒙速办
技术负责人: 张三
联系电话: 13888888888
```

### 二、网络策略申请

需要提供以下信息用于向自治区申请开通网络策略：

```yaml
# 应用信息
应用名称: "[由厂商提供，如：缴费应用、查询应用]"
应用地址: "www.example.com"  # 必须注明访问协议（HTTP/HTTPS）
```
> **重要提示**：网络策略开通周期约为1-2周，请谨慎规划应用地址，避免频繁变更。

### 三、应用接入配置

在网络策略开通期间，可以同步进行应用接入配置工作（注：此阶段无法进行最终测试）。

#### 接入方式选择

##### 1. 托管包方式

将应用前端文件打包（ZIP格式）并上传，需遵循以下规范：

  - 压缩包命名规则：使用应用上下文命名
  - 文件结构要求：
  - 根目录名称必须为应用上下文
  - 前端文件放置在根目录下
  - HTML文件必须位于最外层
  - 测试要求：每次测试需重新上传提交

##### 2. 链接方式

  - 直接提供应用访问链接
  - 需要配置Nginx访问规则：
  ```nginx
  # 在nginx.conf中配置location
  # 确保可通过 应用地址/上下文 访问
  # 示例：www.example.com/123456
  ```

### 第三方厂商访问

**解决方案**：使用融合平台公网地址：http://117.161.199.28:9013/simple/

### IOS访问异常
**问题**：上传托管包应用后，安卓扫码正常，IOS报错  
**解决方案**：检查接口是否为https，因为iOS系统限制接口必须为https

## 一、应用接入问题

### 1.1 应用接入流程
**问题描述**：应用接入的正确流程是什么？  
**解决方案**：
1. 先创建版本
2. 版本审核（由盟市管理员进行）
3. 版本变更后进行测试（需使用蒙速办扫描测试二维码）
4. 测试无问题后提交上线
5. 由自治区管理员进行审核

### 1.2 托管包白屏问题
**问题描述**：托管包形式接入应用，扫码测试时白屏  
**解决方案**：
  - 本地打开html文件检查是否白屏
  - 如果本地也白屏，说明静态文件路径有问题，导致html页面读取不到静态资源

### 1.3 托管包504错误
**问题描述**：托管包形式接入应用，扫码测试出现504 gateway或internal server error  
**解决方案**：检查前端包格式，确保：
  - 压缩包名称为应用上下文
  - 压缩包中文件夹名称为应用上下文
  - 文件夹内放置前端文件
  - html文件必须在最外层

**常见错误**：
1. 压缩包中直接放前端文件，没有应用上下文命名的文件夹
2. 压缩包没有以应用上下文命名
3. 压缩包中的文件夹没有以应用上下文命名

### 1.4 外部接入问题
**问题描述**：外部链接接入相关问题  
**前提条件**：需要开通融合平台服务器（10.3.248.98、10.3.248.102-104）访问目标域名或者ip：port

## 二、API代理调用问题

### 2.1 接口超时问题
**问题描述**：API代理之后，测试接口提示timeout  
**解决方案**：开发商必须开通策略，允许融合平台服务器（10.3.248.102-104）访问接口的ip和端口

### 2.2 API调用地址
**问题描述**：API代理之后调用的地址是什么  
**解决方案**：在首页-服务中心-找到自己发布的服务中查看

### 2.3 API调用方法
**问题描述**：代理API后，如何调用已代理的API接口  
**解决方案**：
  - 需要拼接5个头参数才可以调用
  - java样例可在融合平台的服务中心-任意服务-调用示例中查看
  - 可提供postman调用示例

### 2.4 服务申请问题
**问题描述**：调用代理API时提示该用户未申请服务  
**解决方案**：
1. 开发商需要到服务中心找到自己的服务
2. 点击立即申请
3. 等待系统管理员审核通过后即可调用

### 2.5 签名参数说明
**问题描述**：调用代理API时，头参中的"x-aep-signature"中用到的appkey和appsecret来源  
**说明**：
  - 融合平台有两处需要生成签名signature：
  1. 调用代理API的头参中（使用用户密钥，即用户中心的密钥管理）
  2. auth认证的接口中（使用应用密钥，即应用管理中的应用key和secret）

## 三、auth认证接口问题

### 3.1 认证接口调用
**问题描述**：auth认证的第一个接口如何调用  
**说明**：auth认证第一个接口不需要开放商来调用，应用在蒙速办上授权后会自动调用

### 3.2 认证参数获取
**问题描述**：auth认证第二个接口的入参code从哪里获取  
**说明**：
  - 蒙速办用户授权成功后会跳转到回调页面
  - 在回调页面地址后面会拼接有code参数
  - 开发商直接获取即可
  - 注意：每次授权成功后产生的code都不同且唯一，每个code的有效期为5分钟
 > 📎 **要点提示**：如在调用auth接口时返回“暂未开放的授权模式”,则把调用方式改成表单形式。
 **问题详解** 加上header: {'Content-Type': 'application/x-www-form-urlencoded' }就好了，白屏是因为打包的时候指定了固定的上下文，改成相对上下文就好了
